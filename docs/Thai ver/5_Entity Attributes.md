# 5. การกำหนดแอตทริบิวต์ของแต่ละเอนทิตี (Entity Attributes)

## โครงงานฐานข้อมูล 3DPrinter-Store

เอกสารนี้อธิบายแอตทริบิวต์ของเอนทิตีทั้ง 8 ตารางในฐานข้อมูล MariaDB โดยคำว่า **ตรวจสอบแล้ว** หมายถึงข้อมูลจาก `SHOW CREATE TABLE` ของตาราง `product`, `cartitem` และ `orderitem` ที่ได้รับการยืนยันในโครงงาน ส่วน **รอตรวจสอบ** หมายถึงยังไม่ได้ตรวจสอบ DDL ของตารางจริงครบถ้วน จึงไม่ควรสมมติชนิดข้อมูลหรือข้อกำหนดเอง

**สัญลักษณ์:** PK = คีย์หลัก, FK = คีย์นอก, UQ = ค่าห้ามซ้ำ, NULL = อนุญาตให้ว่าง

## 5.1 `user` — บัญชีผู้ใช้และผู้ดูแลระบบ

| แอตทริบิวต์ | หน้าที่ | คำอธิบาย | สถานะ |
|---|---|---|---|
| `user_id` | PK | รหัสระบุบัญชีผู้ใช้ | ชนิดข้อมูลและข้อกำหนดรอตรวจสอบ |
| `full_name` | — | ชื่อผู้ใช้หรือชื่อ-นามสกุล | รอตรวจสอบ |
| `email` | คีย์ที่อาจกำหนดไม่ให้ซ้ำ | อีเมลสำหรับเข้าสู่ระบบ | ต้องยืนยันข้อกำหนด UNIQUE |
| `password_hash` | — | รหัสผ่านที่ผ่านการแฮช ไม่เก็บรหัสผ่านแบบข้อความปกติ | รอตรวจสอบ |
| `address` | — | ที่อยู่ที่บันทึกไว้เพื่อใช้จัดส่ง | รอตรวจสอบ |
| `role` | — | สิทธิ์ของลูกค้าหรือผู้ดูแลระบบ | ชนิดข้อมูลและค่าที่อนุญาตรอตรวจสอบ |

> หากตารางจริงมีแอตทริบิวต์เพิ่มเติม เช่น `phone` หรือวันเวลาที่สร้างบัญชี ให้เพิ่มหลังตรวจสอบ `SHOW CREATE TABLE user`

## 5.2 `brand` — ยี่ห้อและผู้ผลิต

| แอตทริบิวต์ | หน้าที่ | คำอธิบาย | สถานะ |
|---|---|---|---|
| `brand_id` | PK | รหัสยี่ห้อสำหรับอ้างอิงจากสินค้า | ชนิดข้อมูลและข้อกำหนดรอตรวจสอบ |
| `brand_name` | — | ชื่อยี่ห้อหรือผู้ผลิต | ตรวจสอบความยาว NULL และ UNIQUE เพิ่มเติม |

## 5.3 `category` — หมวดหมู่สินค้า

| แอตทริบิวต์ | หน้าที่ | คำอธิบาย | สถานะ |
|---|---|---|---|
| `category_id` | PK | รหัสหมวดหมู่ | ชนิดข้อมูลและข้อกำหนดรอตรวจสอบ |
| `category_name` | — | ชื่อหมวดหมู่ที่ใช้กับตัวกรองสินค้า | ตรวจสอบความยาว NULL และ UNIQUE เพิ่มเติม |

## 5.4 `product` — รายการสินค้า (**ตรวจสอบแล้ว**)

| แอตทริบิวต์ | ชนิดข้อมูล MariaDB | คีย์ / เงื่อนไข | คำอธิบาย |
|---|---|---|---|
| `product_id` | `INT(11)` | PK, AUTO_INCREMENT, NOT NULL | รหัสสินค้า |
| `sku` | `VARCHAR(50)` | UQ, NOT NULL | รหัสจัดเก็บสินค้า (SKU) |
| `product_name` | `VARCHAR(150)` | NOT NULL | ชื่อสินค้า |
| `description` | `TEXT` | NULL | รายละเอียดสินค้า |
| `image_url` | `VARCHAR(255)` | NULL | URL หรือพาธรูปสินค้า |
| `unit_price` | `DECIMAL(10,2)` | NOT NULL, CHECK ≥ 0 | ราคาขายปัจจุบัน |
| `stock_quantity` | `INT(11)` | NOT NULL, DEFAULT 0, CHECK ≥ 0 | จำนวนคงเหลือ |
| `brand_id` | `INT(11)` | FK → `brand.brand_id`, NULL | ยี่ห้อของสินค้า |
| `category_id` | `INT(11)` | FK → `category.category_id`, NULL | หมวดหมู่ของสินค้า |
| `is_active` | `TINYINT(1)` | NOT NULL, DEFAULT 1 | สถานะแสดงสินค้า / ซ่อนสินค้า (soft delete) |

## 5.5 `cart` — ตะกร้าสินค้า

| แอตทริบิวต์ | หน้าที่ | คำอธิบาย | สถานะ |
|---|---|---|---|
| `cart_id` | PK | รหัสตะกร้าสินค้า | ชนิดข้อมูลและข้อกำหนดรอตรวจสอบ |
| `user_id` | FK → `user.user_id` | ผู้เป็นเจ้าของตะกร้า | ตรวจสอบ NULL และ UNIQUE เพื่อยืนยันว่าผู้ใช้มีตะกร้าได้ไม่เกินหนึ่งใบ |

> คอลัมน์เวลาอื่น ๆ และเงื่อนไขการลบของ FK ต้องตรวจจาก DDL จริง

## 5.6 `cartitem` — รายการสินค้าในตะกร้า (**ตรวจสอบแล้ว**)

| แอตทริบิวต์ | ชนิดข้อมูล MariaDB | คีย์ / เงื่อนไข | คำอธิบาย |
|---|---|---|---|
| `cart_item_id` | `INT(11)` | PK, AUTO_INCREMENT, NOT NULL | รหัสรายการในตะกร้า |
| `cart_id` | `INT(11)` | FK → `cart.cart_id`, NOT NULL | ตะกร้าที่บรรจุสินค้า; ON DELETE CASCADE |
| `product_id` | `INT(11)` | FK → `product.product_id`, NOT NULL | สินค้าที่เลือก; ON DELETE CASCADE |
| `quantity` | `INT(11)` | NOT NULL, DEFAULT 1, CHECK > 0 | จำนวนที่เลือก |
| `created_at` | `TIMESTAMP` | NOT NULL, DEFAULT CURRENT_TIMESTAMP | วันที่และเวลาที่เพิ่มรายการ |

**ข้อกำหนดห้ามซ้ำแบบหลายคอลัมน์:** `UNIQUE (cart_id, product_id)` ป้องกันสินค้าชนิดเดียวกันปรากฏเป็นหลายแถวภายในตะกร้าใบเดียว

## 5.7 `order` — ข้อมูลหลักของคำสั่งซื้อ

| แอตทริบิวต์ | หน้าที่ | คำอธิบาย | สถานะ |
|---|---|---|---|
| `order_id` | PK | รหัสคำสั่งซื้อ | ชนิดข้อมูลและข้อกำหนดรอตรวจสอบ |
| `user_id` | FK → `user.user_id` | ผู้ทำคำสั่งซื้อ | รอตรวจสอบ |
| `order_date` | — | วันที่และเวลาสั่งซื้อ | ชนิดข้อมูลและค่าเริ่มต้นรอตรวจสอบ |
| `total_amount` | — | ยอดรวมเมื่อสั่งซื้อ | ชนิดข้อมูลและ CHECK รอตรวจสอบ |
| `shipping_address` | — | ที่อยู่จัดส่งของคำสั่งซื้อ | รอตรวจสอบ |
| `status` | — | สถานะ Pending, Paid, Shipped, Delivered, Cancelled ตามโค้ด backend | ตรวจสอบ ENUM หรือข้อจำกัดจริง |

> การเปลี่ยนสถานะที่อนุญาตกำหนดไว้ใน backend ซึ่งไม่จำเป็นต้องเป็นข้อจำกัด CHECK ของฐานข้อมูล

## 5.8 `orderitem` — รายการสินค้าที่สั่งซื้อ (**ตรวจสอบแล้ว พร้อมข้อมูลการปรับโครงสร้าง**)

| แอตทริบิวต์ | ชนิดข้อมูล MariaDB | คีย์ / เงื่อนไข | คำอธิบาย |
|---|---|---|---|
| `order_item_id` | `INT(11)` | PK, AUTO_INCREMENT, NOT NULL | รหัสรายการในคำสั่งซื้อ |
| `order_id` | `INT(11)` | FK → `order.order_id`, NOT NULL | คำสั่งซื้อที่เป็นเจ้าของรายการ |
| `product_id` | `INT(11)` | FK → `product.product_id`, NULL, ON DELETE SET NULL | อ้างอิงสินค้าปัจจุบัน หรือเป็น NULL เมื่อสินค้าถูกลบถาวร |
| `product_name_at_purchase` | `VARCHAR(150)` | NULL (เพิ่มในการปรับฐานข้อมูล) | ชื่อสินค้า ณ เวลาซื้อ |
| `sku_at_purchase` | `VARCHAR(50)` | NULL (เพิ่มในการปรับฐานข้อมูล) | SKU ณ เวลาซื้อ |
| `quantity` | `INT(11)` | NOT NULL, CHECK > 0 | จำนวนที่ซื้อ |
| `price_at_purchase` | `DECIMAL(10,2)` | NOT NULL, CHECK ≥ 0 | ราคาต่อหน่วย ณ เวลาซื้อ |

คอลัมน์สำหรับเก็บชื่อและ SKU ณ เวลาซื้อถูกเพิ่มโดยอนุญาตให้เป็น NULL และมีการเติมข้อมูลย้อนหลังสำหรับคำสั่งซื้อเดิม คำสั่งซื้อใหม่ควรบันทึกสองค่านี้ตอนชำระเงิน ส่วน `ON DELETE SET NULL` ทำให้รายการสั่งซื้อยังคงอยู่แม้ลบสินค้าถาวร

## 5.9 เหตุผลของการเก็บข้อมูลสินค้าซ้ำใน `orderitem`

แม้ `product` จะมีชื่อสินค้า SKU และราคาปัจจุบัน แต่การสั่งซื้อควรเก็บ **ข้อมูล ณ เวลาที่เกิดรายการซื้อขาย (historical snapshot)** เพราะชื่อและราคาอาจเปลี่ยน และสินค้าอาจถูกลบถาวร ดังนั้น `price_at_purchase`, `product_name_at_purchase` และ `sku_at_purchase` จึงเป็นข้อมูลประวัติที่จำเป็น ไม่ใช่ความซ้ำซ้อนที่เกิดจากการออกแบบผิดพลาด

## 5.10 รายการตรวจสอบก่อนส่งงาน

ตรวจสอบตารางที่ยังไม่ทราบรายละเอียดครบด้วยคำสั่ง:

```sql
SHOW CREATE TABLE `user`;
SHOW CREATE TABLE brand;
SHOW CREATE TABLE category;
SHOW CREATE TABLE cart;
SHOW CREATE TABLE `order`;
SHOW CREATE TABLE orderitem;
```

นำผลลัพธ์จริงมาเติมชนิดข้อมูล ข้อจำกัด UNIQUE/NULL และแอตทริบิวต์ที่อาจขาดหายไปในส่วนที่ระบุว่า **รอตรวจสอบ** ก่อนส่งเอกสารฉบับสมบูรณ์ โดยข้อ 7 จะเป็น Data Dictionary ที่ครอบคลุมรายละเอียดจาก DDL จริงทั้งหมด
