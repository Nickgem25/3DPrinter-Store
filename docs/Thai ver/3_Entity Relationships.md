# 3. ความสัมพันธ์ระหว่างเอนทิตี (Entity Relationships)

## โครงงานฐานข้อมูล 3DPrinter-Store

เอกสารนี้อธิบายความสัมพันธ์ระหว่างเอนทิตีทั้ง 8 ตารางในฐานข้อมูล MariaDB โดยระบุคาร์ดินาลิตี (Cardinality) และคีย์นอก (Foreign Key) ที่ใช้เชื่อมโยงข้อมูล

## สรุปความสัมพันธ์

| ลำดับ | เอนทิตีหลัก | เอนทิตีที่เกี่ยวข้อง | ความสัมพันธ์ | คีย์นอก | คำอธิบาย |
|---|---|---|---|---|---|
| 1 | `user` | `cart` | 1 ต่อ 0..1 (ตามการออกแบบ) | `cart.user_id` → `user.user_id` | ผู้ใช้หนึ่งคนอาจมีตะกร้าสินค้าได้หนึ่งตะกร้า แต่ละตะกร้าเป็นของผู้ใช้หนึ่งคน ต้องตรวจสอบว่ามี UNIQUE ที่ `cart.user_id` เพื่อบังคับเงื่อนไขนี้จริง |
| 2 | `user` | `order` | 1 ต่อหลายรายการ (1:N) | `order.user_id` → `user.user_id` | ผู้ใช้หนึ่งคนสั่งซื้อได้หลายคำสั่งซื้อ แต่คำสั่งซื้อหนึ่งรายการเป็นของผู้ใช้หนึ่งคน |
| 3 | `brand` | `product` | 1:N (สินค้าไม่จำเป็นต้องมีแบรนด์) | `product.brand_id` → `brand.brand_id` | แบรนด์หนึ่งมีสินค้าได้หลายรายการ โดย `brand_id` ของสินค้าอนุญาตให้เป็น NULL |
| 4 | `category` | `product` | 1:N (สินค้าไม่จำเป็นต้องมีหมวดหมู่) | `product.category_id` → `category.category_id` | หมวดหมู่หนึ่งมีสินค้าได้หลายรายการ โดย `category_id` ของสินค้าอนุญาตให้เป็น NULL |
| 5 | `cart` | `cartitem` | 1:N | `cartitem.cart_id` → `cart.cart_id` | หนึ่งตะกร้ามีรายการสินค้าได้หลายรายการ แต่รายการสินค้าในตะกร้าเป็นของตะกร้าเดียว |
| 6 | `product` | `cartitem` | 1:N | `cartitem.product_id` → `product.product_id` | สินค้าหนึ่งรายการอาจอยู่ในหลายตะกร้า แต่รายการสินค้าในตะกร้าต้องอ้างถึงสินค้าที่มีอยู่ |
| 7 | `order` | `orderitem` | 1:N | `orderitem.order_id` → `order.order_id` | คำสั่งซื้อหนึ่งรายการมีรายการสินค้าที่สั่งซื้อได้หลายรายการ และแต่ละรายการอยู่ในคำสั่งซื้อเดียว |
| 8 | `product` | `orderitem` | 1:N โดยอาจไม่มีการอ้างอิงหลังลบสินค้า | `orderitem.product_id` → `product.product_id` | รายการสั่งซื้ออ้างถึงสินค้าได้ตามปกติ แต่เมื่อสินค้าถูกลบถาวร คีย์นอกจะเปลี่ยนเป็น NULL |

> **หมายเหตุ:** ยังไม่ได้ตรวจสอบคำสั่ง CREATE TABLE ของ `cart` ในรอบจัดทำเอกสารนี้ แอปพลิเคชันออกแบบให้ผู้ใช้หนึ่งคนมีตะกร้าเดียว แต่ฐานข้อมูลต้องกำหนด UNIQUE บน `cart.user_id` เพื่อรับประกันความสัมพันธ์ 1 ต่อ 0..1

## การแปลงความสัมพันธ์แบบหลายต่อหลาย (M:N)

### ตะกร้าสินค้าและสินค้า (`cart` กับ `product`)

ตะกร้าหนึ่งใบมีสินค้าได้หลายชนิด และสินค้าชนิดเดียวกันอาจอยู่ในหลายตะกร้า จึงเป็นความสัมพันธ์แบบ M:N ซึ่งแยกด้วยตารางเชื่อม **`cartitem`**

- `cart` 1 → N `cartitem`
- `product` 1 → N `cartitem`
- `cartitem` บันทึกจำนวนสินค้าที่เลือก (`quantity`)
- UNIQUE (`cart_id`, `product_id`) ป้องกันการมีสินค้าซ้ำเป็นคนละแถวในตะกร้าเดียว

### คำสั่งซื้อและสินค้า (`order` กับ `product`)

คำสั่งซื้อหนึ่งรายการมีสินค้าได้หลายชนิด และสินค้าเดียวกันสามารถอยู่ในหลายคำสั่งซื้อ จึงใช้ตารางเชื่อม **`orderitem`**

- `order` 1 → N `orderitem`
- `product` 1 → N `orderitem` ตราบใดที่ข้อมูลสินค้ายังอยู่
- `orderitem` จัดเก็บ `quantity`, `price_at_purchase`, `product_name_at_purchase` และ `sku_at_purchase`

ข้อมูลชื่อสินค้า รหัส SKU และราคาที่บันทึกขณะซื้อช่วยรักษาประวัติการซื้อไว้ แม้ว่าสินค้าจะถูกเปลี่ยนชื่อหรือลบถาวรในภายหลัง

## กฎความถูกต้องของข้อมูลเมื่อมีการลบ (Referential Integrity)

| ความสัมพันธ์ | การทำงานเมื่อมีการลบ | ผลลัพธ์ |
|---|---|---|
| `product` → `cartitem` | `ON DELETE CASCADE` | ลบรายการสินค้าในตะกร้าที่อ้างถึงสินค้าซึ่งถูกลบถาวร |
| `cart` → `cartitem` | `ON DELETE CASCADE` | ลบรายการสินค้าในตะกร้าเมื่อตะกร้าถูกลบ |
| `product` → `orderitem` | `ON DELETE SET NULL` (หลังปรับโครงสร้าง) | เปลี่ยน `orderitem.product_id` เป็น NULL โดยยังเก็บประวัติรายการสั่งซื้อไว้ |
| `order` → `orderitem` | ไม่ได้กำหนด `ON DELETE` ไว้โดยเฉพาะในโครงสร้างที่ตรวจสอบ | คีย์นอกโดยทั่วไปป้องกันการลบคำสั่งซื้อที่ยังมีรายการสินค้าอ้างอิง |
| `brand` → `product` | ไม่ได้กำหนด `ON DELETE` ไว้โดยเฉพาะ | ไม่สามารถลบแบรนด์ที่มีสินค้าอ้างอิงโดยไม่จัดการข้อมูลที่เกี่ยวข้องก่อน |
| `category` → `product` | ไม่ได้กำหนด `ON DELETE` ไว้โดยเฉพาะ | ไม่สามารถลบหมวดหมู่ที่มีสินค้าอ้างอิงโดยไม่จัดการข้อมูลที่เกี่ยวข้องก่อน |

### ตัวอย่างการลบสินค้าถาวร

ก่อนลบ:

- มีข้อมูลสินค้า `product.product_id = 101`
- ตาราง `orderitem` อ้างถึง `product_id = 101` และบันทึกชื่อสินค้า SKU จำนวน และราคาขณะซื้อไว้แล้ว

หลังลบ:

- แถวของสินค้าใน `product` ถูกลบ
- `orderitem.product_id` เปลี่ยนเป็น `NULL`
- ชื่อสินค้า SKU จำนวน ราคาขณะซื้อ และยอดรวมคำสั่งซื้อยังคงอยู่
- เว็บไซต์สามารถแสดงข้อความ **Product deleted** ในประวัติคำสั่งซื้อได้

**การซ่อนสินค้า (Soft Delete)** แตกต่างจากการลบถาวร โดยตั้งค่า `product.is_active = 0` เพื่อซ่อนสินค้าจากหน้าร้าน แต่ยังเก็บข้อมูลและความสัมพันธ์เดิมไว้

## แนวทางวาด ER Diagram

แนะนำให้ใช้สัญลักษณ์ **Crow's Foot** โดยแสดงข้อมูลต่อไปนี้

1. คีย์หลัก (PK) และคีย์นอก (FK)
2. ความสัมพันธ์แบบ 1:N ของผู้ใช้ คำสั่งซื้อ ตะกร้า แบรนด์ และหมวดหมู่
3. ความเป็นทางเลือก (Optionality) ของฟิลด์ที่อนุญาตให้เป็น NULL ได้แก่ `product.brand_id`, `product.category_id` และ `orderitem.product_id`
4. ตารางเชื่อม `cartitem` และ `orderitem` สำหรับแปลงความสัมพันธ์ M:N

## สิ่งที่ควรตรวจสอบก่อนส่งงาน

ตรวจสอบโครงสร้างจริงของตารางที่เหลือ โดยเฉพาะ `user`, `cart` และ `order` ด้วย `SHOW CREATE TABLE` เพื่อให้จำนวนความสัมพันธ์ การกำหนด NULL และกฎการลบใน ER Diagram ตรงกับฐานข้อมูลที่ใช้งานจริง
